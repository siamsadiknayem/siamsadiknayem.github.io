## Architecture: design and content are separate

```
content/                   CONTENT (Siam edits)
  _data/                   (data_dir) profile, research, publications, courses, news,
                           leadership, timeline, projects, honours, navigation
    materials/<slug>.yml   HAND-EDITED lecture titles, grouping, credits, hidden ids
    drive/<slug>.json      GENERATED by scripts/sync_drive.py: never hand-edit
  _posts/ _drafts/         articles (collections_dir: content)
  _albums/                 "albums" collection → /gallery/<name>/ (front matter: title, date, location, description, cover, photos[file,caption]); _TEMPLATE.md is unpublished
  _pages/                  "pages" collection, front matter + text only:
                           home, about (bio in Markdown), research, publications,
                           teaching, projects, cv, updates, 404, courses/<slug>
files/                     UPLOADS: images/siam.jpg, CV PDF, images/posts/, gallery/<album>/
_layouts/                  DESIGN: default → page → about|research|publications|
                           teaching|projects|cv|updates|notfound ; home ; course ; post
_includes/                 head, header, footer, pub, course-groups,
                           course-materials, material-row
assets/css/main.css        all styles (design tokens at the top)
_config.yml                data_dir, collections_dir, collections.pages, plugins
scripts/sync_drive.py      Drive API → content/_data/drive/*.json
scripts/sync_gallery.py   CI: Drive "Website Gallery" (id in content/_data/gallery.yml) → each sub-folder = album → files/gallery/drive/<slug>/*.jpg + content/_albums/drive-<slug>.md (generated, git-ignored). Captions = Drive description or file name (camera names → none); leading date in folder name = album date; HEIC via pillow-heif; EXIF/GPS stripped
scripts/optimize_images.py CI only: rotate, resize ≤1600 px, strip EXIF/GPS for files/gallery + files/images/posts
.github/workflows/build-and-deploy.yml   sync → jekyll-build-pages → deploy-pages
```

**Email:** every email link uses `{% include email-href.html %}` (Gmail compose URL, optional `subject=`). Never use `mailto:` (Siam's request, 16 Nov 2026).
**Homepage sections:** 01 Research, 02 Publications, 03 Teaching, 04 Leadership, then numbered automatically: My Vision (`content/_data/vision.yml`, Siam's own text, keep verbatim), Gallery (only if albums exist), Updates.
**Always `| relative_url`:** keeps the site working if a baseurl or custom domain is added.

**Rule:** don't put user-facing wording in `_layouts/` or `_includes/`. Page wording belongs in the page's front matter (`content/_pages/*.md`) or in `content/_data/*.yml`. Layouts may only contain structural labels such as section names, "DOI" and "VIEW ↗".

**Testing:**

```bash
jekyll build --safe --config _config.yml,<file with: whitelist: [jekyll-seo-tag, jekyll-sitemap, jekyll-feed]>
```

or `bundle exec jekyll serve`. Posts with a future date are not built: that's the Jekyll default.

### How the course-materials sync works

- `sync_drive.py` uses the Drive API v3 with the `GOOGLE_API_KEY` secret to list each `drive_folder`, plus one level of sub-folders. It writes `content/_data/drive/<slug>.json`, with the fields id, name, title, ext, folder, modifiedTime, view and download.
- If Drive can't be reached, the old JSON is kept. The build continues anyway (`continue-on-error`).
- `_includes/course-materials.html` merges the two sources:
  1. Groups and reading from `materials/<slug>.yml`, matched to Drive files by `id`. A listed id that is missing from Drive is skipped.
  2. Then **"Recently added"**: every Drive file that is neither listed nor in `hidden`.
- The JSON is not committed by the workflow. The copy in the repository is the fallback.

## Conventions

- **Design:** the approved "Concept B revised", the supervisor-first hierarchy.
  - Colours and fonts: white background, ink `#1a1d23`, muted `#5a6170`, a single crimson accent `#9e1b32` used sparingly, IBM Plex Sans and Mono.
  - Each section is a numbered mono label (`01 Research`) beside a content column, under a 1 px ink rule.
  - No gradients, shadows, rounded cards, decorative icons or animations.
  - **Viewer display settings** (added 16 Nov 2026 at Siam's request): a small gear button, fixed to the middle of the right edge of the screen (stays put while scrolling), lets visitors pick a colour theme (Crimson default, Navy, Forest) and Light / Dark / Auto. Labels: `content/_data/themes.yml`. Colours: `--accent-light` / `--accent-dark` per theme and the dark-scheme block at the top of `main.css`; never hard-code `#fff` or greys, use `--bg`, `--surface`, `--on-ink`. Script: `assets/js/theme.js` (vanilla, saves to localStorage); a tiny inline script in `head.html` applies the saved choice before paint.
- **Homepage order:** hero (name, roles pill, bold question `statement`, `intro_lead`, `intro`, `intro_more` — all in profile.yml, PHD line, buttons | photo, positions, education, seeking) → 01 Research → 02 Publications → 03 Teaching → 04 Leadership → 05 Updates.
- **Content lives in `_data` and Markdown.** Layouts should only change for design work.
- **Only GitHub-Pages-safe plugins:** jekyll-seo-tag, jekyll-sitemap, jekyll-feed. Add no JS frameworks.
- **Always use `| relative_url`** for internal links and assets, so a custom domain or baseurl keeps working.
- **Accessibility:**
  - real `<a>` and `<button>` elements, focus outlines, `aria-current` in the nav;
  - alt text on every image;
  - tap targets of at least 44 px for buttons;
  - text contrast of at least 4.5:1;
  - external Drive links use `target="_blank" rel="noopener"` and say "opens in a new tab" in their aria-label.
- **Inside includes, don't name a local variable after the include file.** For example, in `pub.html` the item is `item`, not `pub`. Plain Liquid shadows such names.
